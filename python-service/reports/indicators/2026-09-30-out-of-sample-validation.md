## 验证设计

分两段，**候选只在样本内选，样本外只检验选出的候选**：

| 段 | 区间 | N（无条件基线） | 5 日漂移 | 20 日漂移 |
|---|---|---|---|---|
| 样本内 | 2021-09-13 → 2023-12-31 | 2,632,249 | +0.12% | +0.44% |
| 样本外 | 2024-01-01 → 2026-09-30 | 3,499,890 | +0.47% | +1.80% |

日期过滤放在 **Python 侧按触发日做**，不进 SQL 的 `WHERE` —— 放进 `WHERE` 会先删行
再做窗口函数，`compute: frontend` 的 MACD/KDJ 就从起始日重新起种子，等于**检验时
换了一套序列**。样本外验证最忌讳这种偷偷换口径。

## 怎么读

**MACD 20 日是唯一站得住的信号。** 两段方向一致（+0.82% → +1.13%），原始 p 稳定
（0.0184 → 0.0161），效应量远超 0.2% 的经济阈值，样本外 BH 后仍显著。

它是这套体系里**第一个经过完整验证的可用结论**：金叉之后持有 20 个交易日，
比死叉之后高约 1.1%（同一基准、同一批标的）。

**白线 20 日被否。** 样本内 −1.02% 反向显著（BH 0.044），看起来是个惊人发现；
但样本外变成 +0.86%、p=0.227，**方向翻转且不显著**。这是区间特有的巧合。

顺带一个警示：白线在样本内 5 日是 +0.15%、20 日是 −1.02%，**同一指标在不同
周期上方向相反**；全周期合并后是 +0.13%、不可判定。两个子区间互相抵消掉了它。
**只看全周期会把这个信号抹平，只看样本内又会把它放大成"发现"。** 两个都不够。

## 为什么不直接看全周期

全周期（2016-09 → 2026-09）的配对检验是 0/9 通过 —— 看起来"什么都没有"。
但那是**把两个方向相反的子区间平均掉了**的结果。

正确的读法是分两段看：样本内找出候选，样本外检验。全周期只用来确认没有更长期的漂移。

## 已知局限

1. **幸存者偏差（严重）** —— 5572 只全部在基准日前 90 天内有行情，退市证券 **0 只**。
   起始 90 天在库仅 2708 只，2800 只增量全是 IPO。死票从未进分母，
   **所有胜率与均值系统性偏高**。**本报告不可对外引用。**
   修复需从上游 `a-stock` 代码表补回历史退市证券。
2. **ST 股涨跌停未处理** —— 无证券简称字段，ST 的 ±5% 特例缺失。
3. **样本外只有约 2.7 年 / 3.5 年** —— 一个周期，不能排除运气。
4. **MACD 20 日这条只有一次验证** —— 建议再留一段（未来数据）复验。
5. **未做筛战力评估** —— 本次是无择时、无选股的**无条件触发**口径。战法价值
   可能在条件化之后（叠加选股池 / 指标共振 / 状态过滤），这是下一刀的方向。
6. **重叠样本** —— 已按触发日聚类，同日跨股票横截面相关仍有残留。

## 复现

```bash
cd python-service
# 全周期
uv run python scripts/eval_trigger_power.py --horizons 5 10 20
# 样本内
uv run python scripts/eval_trigger_power.py --horizons 5 10 20 \
    --from-date 2021-09-13 --end 2023-12-31
# 样本外
uv run python scripts/eval_trigger_power.py --horizons 5 10 20 \
    --from-date 2024-01-01 --end 2026-09-30
```

**运行约束**：`~/.hithink-finance` 三个库由 launchd 定时同步持有
（daily-sync 工作日 17:30 / indicators-sync 19:00 / night-sync 03:00），
DuckDB 写锁独占。建议排在 **19:30 之后、03:00 之前**；脚本会自等并把基准降级到
本地缓存，但实测单次同步持锁可超 30 分钟。
