# 金融工作台 —— 决策记录

2026-10-19 对工作台做了一次全面盘问（grill），把「工作台往哪走」这组问题
逐题定案，随后按这些决策执行了第一轮。

格式照 [`../watchlist-diary-decisions.md`](../watchlist-diary-decisions.md)：
每题写清选项、选哪个、为什么。**结论会过期，理由更容易过期** —— 改结论时
连理由一起改，别让理由和结论对不上。

## 一轮盘问（Q1–Q14）

### Q1 —— 工作台的第一任务是什么？

- **A（已选）** 收盘后扫一眼的市场速览（大盘大屏为主角，自选/龙虎榜/ETF 为辅）
- B 盘中盯盘 + 预警
- C AI 投研陪伴
- D 公众号内容消费

**选 A**。① 既有设计文档的原话就是「每天收盘后扫一眼」；
② 底座是 T 日晚 ETL 落盘，盘中无新数据 —— B 是数据源工程问题不是界面问题；
③ MarketDashboard 已是一屏无滚动的成品，B/C 要重排信息架构。
**这不等于放弃 C** —— C 挂在个股详情层（行内日记、HALO 弹窗）位置本来就对：
**大盘扫读、个股深挖、结论要证据**。

### Q2 —— 手上那 7,321 行怎么落地？

- **A（已选）** 切 4~5 条可独立回滚的提交序列
- B 一次提交落地
- C 先合进 mine 再回头拆

**选 A**。`GIT_WORKFLOW.md` 定死 mine 只增不改、NEVER rebase；
7,321 行挤成一条 commit 后想回滚其中 20% 就只能整条 revert。
**切点用模块边界切，不用文件切。**

> 执行时发现：暂存区里只有「改动过的旧文件」，**44 个新文件从未被 stage**
> （22 个新 Go 工具、8 个新 python 模块、4 个新 Vue 组件、9 个新测试）。
> 按原样提交，`python-service` 直接 import 失败 —— 提交序列要按模块重新归位。

### Q3 —— 两条数据面要不要合成一条真源？

- **A（已选）** 保持分层（前端→python-service、agent→Go tools），
  但把共享口径抽成机器可校验的契约
- B 前端也改走 Go
- C agent 也改走 python-service
- D 暂不动

**选 A**。B/C 都是大重构，会把 7,321 行未提交改动和架构迁移叠在一起，回归面乘二；
A 的成本只是一份 schema 契约 + 一个测试，收益是挡住「同一屏两个数不一样」这个
最伤信任的问题。**前置是先把 pytest 的 91 个孤儿测试修进来**（见 Q11）。

### Q4 —— 公众号工作台：iframe 是不是终局？

- **A（已选）** iframe 保留为终局，本轮收三件事：URL 可配置、token 握手、
  postMessage 双向 + origin 钉死；顺带删死代码和孤儿 i18n
- B 收回本体（把 chatlog 的 feed 搬回 WeKnora）
- C 彻底拆开
- D 现状不动

**选 A**。chatlog 是独立项目（Go+Gin+Vue，60 条 `/api/v1/biz` 路由），
它同时是采集源 + 展示源 + 自己的 LLM；在 WeKnora 里重建一套是造第二个产品。
但 A 的三件事**不改架构也得做** —— 服务不在就是一片 `ERR_CONNECTION_REFUSED`，
开了 auth 就是 401。

> Q11 追加的子题：iframe 显示的是 chatlog 全量 67 个号的内容，而 WeKnora KB
> 侧是默认拒绝（18 个无条件 + 条件准入）。**选「接受两处不同，但把语义讲清」**：
> iframe = 素材全量（管理视角），KB = 可被 RAG 引用的可信语料（生产视角）。
> 入库闸门不等于展示闸门。

### Q5 —— 工作台上「结论」的准入门槛？

- **A（已选）** 分层准入：技术读数直接显示；形态标注显示但强制标「仅形态，非建议」；
  策略级信号在有 edge 证据前不得进通知/建议通道，只能当图上描述层
- B 全部加置信度标签就够
- C 维持现状
- D 一刀切：有 replay 证据的才展示

**选 A**。B1 的问题不是「不准」而是**没有 edge**：胜率 40~43%、中位数全负，
作为图上描述层没问题，作为「有建仓波所以买」就是误导 —— 而当时的调色板
正是在做后者。标签会被忽略，通道不会。

> 执行时补了一条硬要求：**descriptive 的形态必须披露确认延迟**。
> B1 的判据循环 `range(25, len(bars)-3)` 意味着形态要到 D+3 才成立，
> 而报告是按 D+1 入口测的 —— 延迟不是结论的原因（按 D+4 重测仍无 edge），
> 但**延迟必须说**，否则图与事实差 3 根 bar。

### Q6 —— 移动端 / 小程序这条线现在做不做？

- **A（已选）** 明确 desktop-only，把这件事写进 AGENTS.md
- B 本轮补最小断点
- C 把工作台搬进小程序
- D 等

**选 A**。现在做响应式要在 5 个千行文件 + 6 个零断点组件上铺断点，
成本高、收益不确定；实际场景是收盘后坐下来一屏扫完，本就桌面。
写下 desktop-only 只要 5 分钟，能省掉未来每个 agent 的猜测成本。

### Q7 —— nginx 那 13 个端点怎么治？

- **A（已选）** 立刻补齐 + 加守卫（断言「每条路由都在 nginx 白名单里」）
- B 立刻补齐 + 写生成脚本
- C 立刻补齐，手工同步，不加守卫

**选 A**。守卫比生成脚本合适：nginx.conf 是部署产物，可能有环境特有条目，
生成器会覆盖人加的东西；断言是「只检查、不改写」，误报为零。

### Q8 —— 表面缺陷怎么打包？

- **A（已选）** 打包成一个提交，一次清完
- B 分散到各功能提交
- C 只修用户真能看见的

**选 A**。互不耦合、都是「看一眼就知道对不对」的验收标准，打包后一次可整体验收。
深色主题不跟随是里面最严重的 —— 它不是「不好看」，是「看错」。

### Q9 —— 本轮重构范围划到哪？

- **A（已选）** 只做：拆 main.py 路由目录 + 收敛 K 线双外壳到共享内核；
  四个 Vue 巨组件不拆
- B 只做 K 线内核收敛
- C 全做
- D 都不做

**选 A**。原则：**拆正在写的，不拆正在稳定使用的**。四个 Vue 巨组件刚被改动过，

### Q10 —— 测试网先补哪一层？

- **A（已选）** 三步：修 pytest testpaths → api 模块的 URL 构造抽纯函数并测 →
  只给 2 个高价值点写组件测试
- B 先铺组件测试，覆盖率优先
- C 只修 testpaths

**选 A**。B 会引入 `@vue/test-utils` 依赖 + 拖慢 CI，与本仓库「纯函数 + 单测」
的测试文化相悖。

### Q11 —— 「什么值得推」怎么统一？

- **A（已选）** 页面是唯一主出口，但**统一一个通知原语**：一套「什么值得推」
  的判定（频率上限 + 去重 + 静默时段 + 渠道）供三类消费者共用；日记继续不推飞书
- B 维持三套各写各的
- C 工作台补一个统一通知中心
- D 把日报也拉进工作台

**选 A**。三个推送各写一套，规则会漂，且漂的方向通常是「越来越爱推」。
A 把「什么值得推」抽出来共用，日记仍然不推（策略层决定），但以后想开一个
开关就行，**不用重写推送逻辑**。D 会把对外内容产品拖进主线心智。

### Q12 —— pytest 里 91 个测试为什么不跑？

- **A（已选）** 修 testpaths，让它们进 CI
- B 留着，它们测的是内部实现

**选 A**。`pytest.ini` 的 `testpaths = tests` 让 `finance_panel/tests` 与
`etfholdings/tests` 里的 91 个测试函数**从未被收集** —— CI 一直在空跑它们，
这两个目录等于没有回归网。修完之后，18 个失败里有 14 个自己就绿了。

### Q13 —— 文档做到哪一档？

- **A（已选）** 三件套：工作台全貌 + 本决策记录 + tech-debt 增补一节，
  之后不再新增大文件
- B 只在 AGENTS.md 加一节
- C 不写文档，靠 commit message

**选 A**。tech-debt 已有 10 个文件 25 万字符，再加就是第 11 个大文件、
下一个人不会读。本仓库的风格「决策过程比结论更有用」值得保留，但工作台
现在缺的不是过程记录，是**一张地图**。AGENTS.md 是给 agent 的硬约束，
工作台全貌是给人的地图，受众不同，不能互相替代。

### Q14 —— 遇到不是自己造成的坏怎么办？

- **A（已选）** 在同一工作范围内一并修掉，并把根因写进提交信息
- B 单独开一个待办
- C 记进 tech-debt

**选 A**，但**只限「明确坏掉、且修法唯一」的那类**。发现时的判断顺序：
① 会不会被 CI 拦住？② 修法唯一吗？③ 与本次改动同属一个范围吗？
三个都是才顺手修；否则老实记进 tech-debt。

## 执行期追加的决策

### Q15 —— pytest 的日期固化用例怎么修？

- **A（已选）** 改测试：以「最近的工作日」为锚点、用相对天数构造
- B 改服务：让新鲜度只看请求日
- C 加一个今天的日期夹具

**选 A**。服务的两层判定（相对请求日的滞后 > 5 天 / 相对今天的绝对滞后 > 12 天）
**行为是对的** —— 19 天前的缓存确实过期了。腐烂的是测试：它把「当天」写死成
2026-09-30，过了那天自己开始失败。改服务去迁就测试是本末倒置。

### Q16 —— K 线双外壳本轮要不要一起收？

- **A（已选）** 先只收敛**重复的那部分**（建图选项），数据路径与指标集
  保持各自的 —— 那些差异是外壳的设计，不是同一件事写了两遍
- B 一次性全收：统一数据路径与指标口径
- C 完全不收

**选 A**。两个外壳的 init options（locale / 时区 / X 轴日期格式）是逐字复制的
一份 —— 同一只票在两处画出来，X 轴格式得一样，否则两处的读数没法互相印证。
这部分收敛是**行为零变化**的。

而数据路径（轻量图取 120 根 bar、重工作台走 datafeed 的 5000 根）与指标集
（轻量图只要 MA + 成交量、重工作台有完整图层体系）是**外壳的设计**：
窄侧栏塞 5000 根 bar 是浪费，重工作台只放 MA 是信息不足。
强行统一它们会改变渲染结果 —— 那该单独做、单独验。

> 2026-10-20 落地：抽出 `coreChartOptions(styles)` 到 `core-chart.ts`，
> 两个外壳都从那里取；画布配色仍由调用方给（重的固定深色、轻的跟随主题）。
> 新增两条断言盯住收敛：两边都不得再出现抄写的 init options。

### Q17 —— python-service 的 main.py 拆几个模块？

- **A（已选）** 3 个 router 模块 + 一份共享 core
- B 7 个模块（按更细的业务域切）
- C 不拆

**选 A**。先落地可跑、全绿的一版，比一次拆到位更重要。`STRATEGY_RULES` 因为
被一个 Go 测试正则解析源码文本，不能搬走 —— 这是跨语言源码耦合的实例，
记在提交信息里。

### Q18 —— 「形态 ≠ 信号」的披露落在哪几层？

- **A（已选）** 三层同时：后端 metadata 带着延迟与档位、前端悬浮说明自动拼披露、
  文档里写判据与定档流程
- B 只在前端显示一句提示
- C 只写文档

**选 A**。只在界面写一句提示，换个入口（agent 接口、脚本）就漏了；
只在文档写，没人看。**延迟要机器可读**：后端 metadata 带
`confirm_delay_bars` / `detectable_at` / `admission`，任何消费方都能拿到。
