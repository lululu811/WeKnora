# 大盘预览大屏 —— 重设计候选：墨账

2026-10-20 对 `/dashboard`（大盘预览大屏）做了一次重设计落地。方向是从
tasteskill 的 app-screen 库里 deal 出来的三套风格里选定的 **02 墨账**
（`achromatic-ledger`），并按「不破坏已实现结构」的方式落到生产组件里。

格式照 [`finance-workbench-decisions.md`](finance-workbench-decisions.md)：
每题写清选项、选哪个、为什么。**结论会过期，理由更容易过期**。

## 背景：这面屏已经有方向了

`docs/design/market-dashboard/` 里躺着一版**已定稿并已实现上线**的方向
「晨间行情桌」：衬线标题 + 珊瑚只做状态与焦点，记忆点是指数格的
「当日快照条」（低—高区间轨道上标今开刻度与最新点，不靠分时数据也能读出
日内位置）。独立评审两轮 8.5/10 判定「可以走实现」，实现在
`frontend/src/finance/views/MarketDashboard.vue`（1765 行，路由 `/dashboard`）。

所以这一轮**不是绿地设计，是重设计候选集** —— 真问题是：已定的记忆点还
站得住吗？

### Q1 —— 为什么还要重设计？

- **A（已选）** 现状的首屏主角是**四大指数走势 2×2**，但这屏真正的题眼是
  赚钱效应。2026-10-19 的数据把话说明白了：**6 只宽基全涨、3 只成长全跌；
  涨停 49 家里 77.6% 是首板，4 板以上今天断档，最高板从 7 板掉到 3 板。**
  指数 2×2 把读者的第一眼给了涨跌幅，把「钱在进还是在退」这个真正的问题
  压到了右侧陪衬位。
- B 现状已经评审过 8.5/10，不该动
- C 换个配色就行

**为什么选 A**：上轮评审记录里反复出现的两条软肋就是「情绪格 40% 死白」
与「指数卡无参照系」—— 两者都指向同一个病：**构图是模板给的，不是这产品
自己的**。重设计要解决的是构图，不是配色。

### Q2 —— 风格选哪套？

deal 出来三套（`--keep palette,type`，品牌基线不动）：

- 01 板层（`accent-ladder`）—— 签名元素是「板层 + 封单杠」
- **02 墨账（`achromatic-ledger`）—— 已选**
- 03 收盘版面（`framed-sheet`）—— 签名元素是「两个世界」的白纸版面

**为什么选墨账**：这屏是**数据屏**，不是叙事页。它需要的不是"记忆点"，
而是**能把一堆数字读成一张表**的秩序。墨账的三条恰好是数据屏需要的：
外壳无色（数字自己说话）、图表用墨色（不把涨跌幅的 1% 放大成一条红线的
心理冲击）、涨跌只给一个 6px 小点（方向靠符号讲，不靠颜色喊）。

板层和收盘版面都更"有性格"，但它们要额外的数据：板层要连板分档明细与
封单金额，收盘版面要每天的涨跌家数与断档判定。**墨账用现有接口就能成立。**

### Q3 —— 改到哪一层？

- **A（已选）** 只改 `/dashboard` 全屏态；个股追踪 tab（`embedded=true`）
  **原样不动**
- B 两个形态一起改成墨账
- C 整个金融模块一起改

**为什么选 A**：个股追踪是**可滚动的工位屏**，块多、每块自带交互，牵连
6 个子组件（竞价 / 板块榜 / 梯队 / 期股 / 热股 / 分红），各带自己的卡片
样式。把它一起改会把这一轮从"改一面屏"变成"重做半个模块"，风险与工期
都不成比例。两个形态在同一个产品里并存是**有意的边界**：一个是独立全屏的
速览，一个是嵌在壳里的工位，用法本来就不同。

### Q4 —— 品牌色与「红＝涨」撞车怎么办？

**这是本轮最实用的一条发现，与选哪个方向无关。**

品牌强调色是**珊瑚 `#E85D3D`**，而 A 股语义里**红＝涨**。两者色相极近。
品牌色一旦铺开成区域色，读者的眼睛会把"这是今天 / 这是重点"读成"这是涨的"。

**已选做法**：三个形态都把**品牌色限制在小标记**上，**涨跌色只上数字**，
两套语义用**位置**分开：板层 / 涨停相关 = 珊瑚，指数涨跌数字 = 红绿。
本轮落地后，全屏**唯一**一处满强度珊瑚是「情绪明细」里「最高空间板」那行
前面的 8px 小方块。

### Q5 —— 数字重复怎么办？

左栏「今日读数」给 5 个数（涨停 / 跌停 / 炸板 / 封板率 / 最高连板），
右栏「情绪明细」又给了同一组数。**这不是同一个事实画两遍**：读数栏是
**摘要**（只给数），情绪明细是**账目**（给数 + 分项 + 算式，例如封板率
那行写明「封板 49 ÷ 触板 69」）。两处都从**同一批 computed 派生**，不会
各算各的。

### Q6 —— 哪些数据拿不到、怎么办？

**不画。** 本轮不扩后端接口（`/api/market/snapshot` 与
`/api/market/dragon-tiger` 够用），因此：

- **近 5 日涨停家数**有（`limit_up_trend`）→ 进「今日发现」的走向判定
- **涨跌家数**有（`breadth`）→ 进「情绪明细」的「上涨家数」行
- **连板分档明细 / 封单金额 / 首板占比**没有 → **一句都不提**，不写"77.6%
  是首板"这种算不出来的话
- 今日发现的走向判定只用**近 5 日涨停家数的首尾比较**，没有数据就整段留空

**宁可少一句，不说假话。**

### Q7 —— 榜单列几行？

接口一次给 50 条龙虎榜、18 只 ETF（`DRAGON_LIMIT = 50`）。现状卡片是靠
**固定高度裁掉**多余的：1440 下露出 **6 条龙虎榜、8 只 ETF**，DOM 里却是
50 / 18 行。墨账版没有卡片可裁 —— 每一行都占真高度，所以显式切到能列下的
行数，并把 caption 改成**说清"列了几条"**的口径（`净买入前 6 · 2026-10-19 ·
全市场`），免得写着「信号 18/18」却一行都没给。

权重 ETF 的 **份额变动 % / 成交放大倍数**必须留在行里 —— 份额变动是
"国家队在不在进出"的唯一证据，价格涨跌只是结果。为了腾出宽度，ETF 行
**去掉了代码**（名称本身就唯一标识，代码在 K 线与 ETF tab 里都有）：半栏
433px 装不下五个字段，这是墨账版比卡片版窄的必然结果，不是丢信息。

### Q8 —— 同一组数在一屏出现三次，是不是把一件事画三遍？

不是。涨停 / 跌停 / 炸板 / 封板率 / 最高连板在**今日读数**（只给数）、
**今日发现**（串成一句话）、**情绪明细**（给数 + 分项 + 算式）各出现一次，
三处**都从同一批 computed 派生**，值不会打架 —— 这是"摘要 + 叙述 + 账目"
三种读法。

# 第二轮 —— 把墨账推到个股追踪的「大盘」tab

2026-10-20。第一轮只改了 `/dashboard` 全屏态，**个股追踪的「大盘」tab 还是卡片版** —— 同一个屏的两种形态两套 chrome，这是第一轮刻意留的边界。第二轮收这个口。

### Q9 —— 这一轮推哪几个面？

- **A（已选）** 只推**个股追踪 → 大盘 tab**（`embedded=true` 形态）：共享块（指数条 / 四大指数卡 / 市场情绪 / 自选股 / 龙虎榜 / 权重 ETF 摘要）+ 6 个子组件（竞价 / 板块榜 / 连板梯队 / 期股联动 / 人气与飙升雷达 / 除权除息日历）
- B 整个个股追踪页四个 tab 一起推
- C 整个金融模块（含 K 线工作台、公众号工作台）

**为什么选 A**：B 覆盖 4500+ 行（自选股 2594 + 详情面板 1990 + 谁在动 960 + ETF 1028），一轮推完既审不动也容易改坏；C 更远。**一轮推一面，验收得干净。** 剩下三个 tab（自选股 / 谁在动 / 权重 ETF）各留一轮。

### Q10 —— 墨账体例写在哪、怎么保证 7 个文件不跑偏？

新建 `frontend/src/finance/styles/ledger.less`：**共享令牌**（`--ledger-ink-1..5` 墨阶）+ **体例规范**（三条规矩写在文件头）。它由 `src/finance/index.ts` 入口做副作用 import，和既有的 `.kline-ticker` 同一个路子 —— 只要金融能力接入主应用，样式就生效。

6 个子组件的**根类卡片外壳写法完全一样**（`background: container` + `1px stroke` + `radius` + `padding`），所以改造是机械的；难的是**内部**哪些颜色是数据、哪些是装饰。三个子任务并行推进，每个都只动 `<style scoped>`。

### Q11 —— 颜色怎么分？

一条规则，两个视图通用：

> **结构性数字用墨色**（收盘价、点位、份额、倍数、名称、代码）；
> **方向靠 6px 小点**；
> **只有"方向本身就是这块主角"的数字才直接染语义色**（涨停红 / 跌停绿、净买入红绿、基差正负红绿）—— 那是 A 股语义，不是装饰。

两处需要说清：

1. **封单金额**原本用**品牌珊瑚**。它是**量级**（涨停时封单只有买盘，没有方向可讲），珊瑚在这里是被当装饰用了 —— 改成墨色。
2. **涨停红 / 跌停绿**在两个视图统一都保留。第一轮的读数栏是纯墨色（摘要），第二轮的嵌入态是红绿（48px 主角）—— 同一组数据两种表达，是第一轮留下的不一致，这轮统一成红绿。

### Q12 —— 块根归零之后，文字贴到屏幕边缘怎么办？

嵌入态的 `.md-page` 原本 `padding: 0`，**内缩是靠卡片自带的 16px padding 撑的**。块根归零后标题就贴到边缘（inspector 的 `edge-text` FAIL）。

修法两步：① `.md-page.is-embedded` 给 20px 内缩；② **`.md-page.is-embedded .md-tile` 的覆盖规则也要归零** —— 它特异度更高（0,3,0），不改的话 `.md-tile` 块在 14px、6 个子组件在 0px，**两列起点错开**。归零后所有块对齐在同一条左边缘。

### Q13 —— 去卡片底之后，红绿数字的对比度降了 0.1，怎么补？

去卡片外壳是一个**有代价**的动作：红绿数字原本压在白卡（`#FFFCF6`）上，
现在直接压暖纸底（`#FAF4EA`）—— 同样一个 `--app-quote-up: #dc2626`，
对比度从 4.6:1 掉到 **4.4:1**，差 0.1 过不了 AA。

**已选做法**：给「市场情绪」块（涨停红 / 跌停绿那两个数）**保留一块纸面**。
两个理由：① 数字回到白纸上，对比度回到 4.6:1；② **全屏版的「今日读数」也是
一块纸** —— 两个视图的读数块长得一样，才叫同一套体例。

**没做的**：竞价块（异动榜的涨跌数字）同样降到 4.4:1，没给它也加纸面。
再给一块纸，这一屏就有两块纸，「墨账」变成「半卡片」；而真正干净的做法是调
`theme.css` 的 `--app-quote-up` 令牌 —— 那是**全产品共用**的涨跌色，改它影响
对话页、K 线、公众号工作台所有界面，不是这一轮该做的。**这 0.1 如实记在这里。**

第二轮完成后派了独立评审（verifier），结论是**有条件通过**：改版本身成立、数据语义没被刷掉，
但有 3 条应修 + 若干建议。**同时它推翻了我自己报告里的三处口径**，一并记在这里：

| 我说过的 | 实际 | 订正 |
|---|---|---|
| 嵌入 tab 是 0 FAIL / **2** WARN | 0 FAIL / **3** WARN | 多一条 `no-data-hue`（墨账规则 2「图表一律墨色」与 inspector「数据要有色相」正面冲突，是**体例本身的代价**，不是缺陷） |
| 自选股价取自 mock 的 10-09 真实价 | **页面渲染的是 10-20 真行情** | vite 把 `/api/quotes` 路由到 python-service 50052，mock 只提供**名单与状态**，价格一直来自真接口。代码里确实没有写死 mock 值 ✓ |
| lint 改前改后都是 0 FAIL / 8 WARN | 该数字只对 `MarketDashboard.vue` 单文件成立 | 覆盖本轮 6 个子组件的范围：HEAD **1 FAIL / 28 WARN** → 现 **0 FAIL / 17 WARN**（净改善） |

**已修的 3 条应修**：

1. 嵌入态的**品牌珊瑚**（龙虎榜榜首「1」、自选股「已触发」徽标）与全屏同数据口径不一致，
   且全产品珊瑚不止一处 → 改成墨色 / 墨阶。
2. **梯队矩阵最浓档白字压墨阶只有 3.08:1**（11px 要 4.5）。根因是**墨阶的方向随主题翻转**

   新增 `--ledger-ink-max` / `--ledger-on-ink-max` 两个随主题的令牌解决。
3. 交付证据与代码脱节（报告说 2 WARN，report.json 已经是 3）→ 重新取证。

**另外做的**：过期注释改掉、`.ledger-block` 工具类**真正用起来**（6 个子组件的根类改为
引用全局类，不再各抄一份归零四行）、删掉 8 处死 CSS（全屏改用 `lg-topbar` 后
`.md-topbar` / `.md-icon-btn` / `.md-status-chip` 模板零引用）、DividendCalendar 剩余 4 处 10px 提到 11px。

# 第三轮 —— 谁在动 / 权重 ETF 两个 tab

### Q14 —— 密集列表里的数字，要不要也改成「墨色 + 小点」？

**不要。** 这是大屏那套写法用错地方了。

大屏的「墨色数字 + 6px 点」成立，是因为那屏是**一屏扫完**的速览：9 行指数表，每行只
看一个涨跌幅，点足够。个股追踪的这三个 tab 是**密集表格**——多列并排（价格 / 涨跌 /
涨跌幅 / 仓位 / 状态 / 份额…），一行里同时出现好几个数，点在多列里读不出来。

**定死一条分界**：

- **数字**（涨跌幅、净买、仓位、份额变动）→ **保留红绿**，数字本身讲方向；
- **图形**（迷你走势、柱、浓淡矩阵）→ 墨色 / 墨阶；
- **状态标记**（已触发 / 已建仓 / 榜首 / 异动）→ 墨阶或灰，**不占品牌珊瑚**。

### Q15b —— 死代码要不要顺手清？

**这一轮没清。** 全屏改用 `lg-topbar` 之后，`.md-topbar` / `.md-icon-btn` /
`.md-status-chip` 在模板里零引用（`.md-etf-row*` 仍活着，别一起删）。评审把它列为
"建议"项是对的，但删它的时候我用正则匹配规则块，**踩到了嵌套规则里第一个 `}` 就停**
的坑，把 Less 切成了括号不平衡、整页白屏。修回来之后决定：**死 CSS 留着，单独一个
清理 commit 处理** —— 一条"建议"不值得拿构建去换。

### Q15 —— 品牌珊瑚全产品只留一处？

**是。** 上一轮全屏版已经把它定成「情绪明细里最高空间板那行的 8px 方块」。
这一轮起，**状态 / 名次 / 触发一律走墨阶或灰** —— 上一轮评审就是拿这条判的：
嵌入态当时有 3 处珊瑚、全屏只有 1 处，两视图口径不一致。

### 第三轮落地结果（谁在动 / 权重 ETF / 自选股）
